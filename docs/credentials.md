# 显式凭据文件

CLI 支持 `--credentials-file <path>`，仅从指定文件读取 `OPENAI_API_KEY`，不自动查找项目目录的 `.env`。文件路径相对于启动命令时的目录，不相对于 `--cwd`。

参数刻意不用 `--env-file`：这是 Node 自己的启动参数，会把整个文件应用到环境，包括 `NODE_OPTIONS`。Pure 的凭据入口只提取密钥，不加载其他进程设置。

```sh
npm start -- --credentials-file /private/location/pure.env --cwd ./your-project --read-only
```

文件使用 UTF-8 dotenv 格式，最大 64 KiB，只允许普通文件；注释、引号和 `export` 前缀按 Node 的 `parseEnv` 规则解析。实际凭据通过安全方式保存到私人文件，不要把密钥放在命令参数、聊天、截图或日志中。不要提交凭据文件。仓库忽略 `.env`、`.env.*` 与 `.private/`，但忽略规则不是访问控制，也不保护其他上传渠道。

- 已设置的进程环境 `OPENAI_API_KEY` 优先；如果显式设为空或空白，则报错，不回退到文件中的另一把密钥。
- 只要给出 `--credentials-file`，就必须能读取这个有效文件，即使进程环境已配置密钥。拼错路径不会静默成功。
- 仅提取 API Key。文件中的 `NODE_OPTIONS`、端点、代理等其他字段不会应用到进程，也不会转发给子进程。密钥在启动时解析一次，`/new` 复用相同值。
- `--help` 不读取凭据。文件错误仅显示固定说明，不回显路径、解析器错误或文件内容。
- 读取文件不验证凭据有效性、账户权限、额度、模型支持或网络。出现 401 仍需要重新配置有效凭据，不自动重试或切换密钥。

建议把文件放在目标工作区外的私人位置，限制文件访问权限。`--trust-workspace` 下的命令仍有宿主权限，可能访问工作区外文件；此功能不是凭据保险库或命令沙箱。凭据不会写入会话快照，但允许读取凭据文件的工具或用户自行复制内容仍可能泄露它。

## 验证边界

`node --test test/credentials.test.ts` 只检查真实临时文件、解析和 CLI 失败前置路径，没有模型、HTTP 替身或模拟模型响应；不证明真实 API 验收通过。质量检查、类型检查和构建同样不证明真实模型行为。

真实 API 验收需在有效凭据安全配置后另行运行，核对实际文件与工具效果并保存脱敏结果。目前不得用模拟模型响应补齐。当前允许的静态、组件及安装包检查见 [验证规则](verification-policy.md)。默认 `npm test`、`npm run check`、`npm run test:package` 明确拒绝；Linux CI 只执行已审阅的非模型检查，不执行历史模型替身。
