# Pure Agent 路线图

这是工程方向与状态快照，不是交付日期承诺。目标是一个**小而有力、可检查的基本 Agent**：同一核心服务 SDK 与 CLI，Dark Deco TUI 提供可观察交互；先把基本单元做好，再验证组合。

## 主干基线

基线提交：`75798b33f1b8444550d188893fab070a632b482c`（2026-11-02 记录）。以下是该提交已有能力，不代表后续分支均已合并：

- 单会话模型 → 工具 → 观察循环，注入模型与工具，顺序执行、步数上限、协作式取消和可观察结果。
- SDK 与 CLI 共用核心；确定性离线演示、官方 OpenAI Responses 适配器与限定文件的只读项目工具。
- 独立 Pi TUI 模块承载编辑、Markdown 与终端交互，Dark Deco 视觉层不引入另一套执行核心。
- JSON Schema 参数校验、SDK / CLI 本地安装包验收与离线 CI 工作流。

该基线已有记录为严格类型检查、108 项离线测试和独立安装包验收通过；此文档变更未重新运行这些检查。真实模型记录只覆盖三轮限定项目资料交互，不是通用准确率、生产验收或账户花费保证。查看 [README](../README.md) 的验证范围与运行命令。

## 开发中：不是主干能力

- `feat/streaming`：模型输出流式呈现，仍需审阅、验收与合并；基线适配器尚不支持流式显示。
- `feat/config`：配置能力改进，仍需审阅、验收与合并；不能据此宣称主干已有该分支行为。

分支可能独立演进；测试数量和成功记录必须绑定具体提交。合并前记录的组合验证，不等于主干 CI 已通过。

## 后续顺序与完成证据

1. **完善基本单元**：以可复现任务检查完成质量、错误路径、取消后继续运行和工具副作用；`completed` 不等于任务正确。
2. **完善 SDK 与 CLI 的一致性**：配置、工具、模型与执行事件可检查、可替换；通过公开接口与包消费者测试证明，而非依赖 CLI 私有能力。
3. **按证据补可靠性**：根据真实失败决定是否增加上下文管理、持久化或权限机制。当前不承诺这些能力，也不为它们先建框架。
4. **再验证多 Agent 组合**：基本单元成熟后才开展最小组合实验；Team、后台调度和管理平台不属于当前交付范围。

## 实现原则

- 务实应用 SOLID：职责分离、窄接口和依赖注入，让适配器可替换；不为未来需求添加空壳抽象。
- 优先复用 Pi 与成熟模块；新增依赖必须说明收益、维护成本和权限边界。不以零依赖为目标，也不复制整套平台。
- 核心不是安全沙箱，取消不会撤销外部操作。宿主负责工具授权、隔离与预算；目前没有账户级花费硬限额。

## 如何复现与参与

按 [贡献指南](../CONTRIBUTING.md) 安装锁定依赖，运行 `npm run check` 和 `npm run test:package`；它们不调用模型 API。真实模型测试需单独确认服务、凭据方式与预算，不是贡献者的默认步骤。

公开进展以小型草稿 PR 为单位，附提交 SHA、实际命令、结果与未验证项。只公开脱敏且审阅过的证据；私人笔记与凭据留在忽略的 `.private/` 或宿主安全配置中。合并、发布与部署是独立动作；当前未确定开源许可证，也未发布 npm 包。
